### 11:00 — parser.py 正则提取

**采购计划编号正则：**
```python
r'采购计划编号[：:\s]*([A-Z0-9]{4,}-[0-9]{4}-[0-9]{5,})'
# 匹配示例: 441301-2025-03605
```

**采购项目编号正则：**
```python
r'采购项目编号[：:\s]*([A-Z]{2,}[-_]?[A-Z0-9]+[-_]?[0-9]{4,}号?)'
# 匹配示例: HZJJ-2025118号
```

**anti-false-positive 过滤：**
- 过滤纯数字结果（避免匹配到页码）
- 过滤包含"电话"的匹配
- 过滤页眉页脚常见固定格式

## 关键教训

### 教训 1：业务编号防重优于名称防重
- project_name 只能做兜底，不能做主要防重依据
- plan_code 是真实业务编号，agency_project_code 是辅助编号
- 双重键防重 = 业务层面的严谨性要求

### 教训 2：关系标识与生成模式必须正交
- "有关系"不等于"必须用GUIDED模式"
- "没关系"不等于"必须用AUTO模式"
- 专员根据项目复杂度独立选择生成模式

### 教训 3：UI表单必须网格化
- 单行铺满 = 低质量后台界面
- el-row/el-col 双列布局是 Element Plus 标准实践
- compact label + 12px margin-bottom 是最小美观配置
