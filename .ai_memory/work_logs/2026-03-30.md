### 10:15 — 澄清端口拓扑

```bash
$ docker ps

```

```bash
$ netstat -ano | grep :8001
TCP    127.0.0.1:8001    0.0.0.0:0    LISTENING    28204
```

**真相：**
- `localhost:8001` = **Anaconda Python 孤儿进程**（PID 28204，Windows 残留）
- `localhost:8000` = **Docker backend**（正确）

## 关键教训

### 教训 1：Docker 端口不能想当然
- `docker compose up -d` 后一定要 `docker ps` 确认物理端口
- `localhost:8001` 可能是任何 Windows 进程，不能假设是 Docker

### 教训 2：`docker compose up -d` 不会自动停止旧容器
- 多次修改配置后重建，应该先 `docker compose down` 再 `up`，或使用 `docker compose up -d --force-recreate`

### 教训 3：DEBUG 注入不显示 = 代码根本没执行
- `raise Exception` 仍然 200 OK = 请求没进目标函数
- 说明路由或端口打到了完全不同的服务

### 教训 4：业务逻辑"粉饰太平"是最高级别 Bug
- `else 100` 在任何场景下都是危险代码
- 评分系统宁可返回 0 分 + 明确错误，也不能给假 100 分
